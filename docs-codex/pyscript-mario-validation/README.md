# Python Mario 阶段四验收证据

实现说明：[阶段四记录](../pyscript-mario-phase4.md)。本阶段交付核心玩法，完整页面控件、平台能力及 Release/长期性能仍待后续阶段。

`final/` 来自 `out/Debug/pyscript-mario-phase4/final-2/` 同一次统一验收。标准五目标构建成功，192 项原生单测、19 项宿主游戏逻辑测试、181 项浏览器测试全部通过，合计 392 项；16 组均为 `verified=true`。验证期间 865 个功能输入文件保持不变。

- [统一汇总](final/summary.json)：`passed=true`、`sourceUnchanged=true`、配置、命令、源码和二进制 SHA-256。`sourceCommit` 是运行开始时的基线，待提交实现按工作树 `sourceSha256` 记录，包含已有文件及新文件；它不是声称基线提交已经包含本阶段实现。
- [构建日志](final/build.log)：标准五目标增量构建成功。本轮无待执行构建步骤；前一次统一验收的 [build.log](probes/first-unified/build.log) 也保留在探测目录。
- [运行时](final/runtime.json)：71 项，包括静态 math、解释器隔离、批量矩形、单次及窗口预算、事件/绘图和清理。
- [Mario 逻辑](final/mario-logic.json)：19 项；15 条原版数值轨迹及固定时钟、频率一致性、随机/效果池、物理软额度。
- [Mario 浏览器](final/mario.json)：24 项，包括原生批量矩形像素/费用、CSP/无 JS 页面、真实可信点击/键盘/指针、暂停/重开/后台恢复、15 条数值轨迹、导航/刷新与退出码为零的正常关闭。
- [准备画面](final/mario.json.ready.png)、[实际输入后的画面](final/mario.json.playing.png)、[整关回放结束画面](final/mario.json.won.png)。均为 1120×900、DPR 1 的 headless 页面截图；保持 Renderer 沙箱，使用软件绘制。
- [静态检查](diagnostics/static-checks.json)：C++/GN 格式、Node/Python 语法、生成页面一致性、checkdeps、差异空白、776 份 CPython 上游文件的 SHA-256 清单。辅助脚本及各项日志一并保存。
- [归档清单](archive-manifest.json)：每个输出的本机来源、原始 SHA-256 和归档 SHA-256。文本统一为 UTF-8/LF，去掉行尾空白及多余 EOF 换行；空日志保持为空，PNG 原样复制。汇总中的原始文件哈希与归档哈希不同时，用此清单关联。

整关数值回放来自默认起点与原版参数，只输入向右及跳跃按下/松开，不改坐标、不无敌、不额外计分。2773 步、23.1083 秒模拟时间，六个检查点；最终 25 金币、5170 分、3 生命、零死亡，途中经过检查点。浏览器每原生回调推进一步，观测、最终构建和提交分别使用独立回调；它验证同一物理代码在嵌入式解释器中的状态，不是人工输入通关或全关实时绘图性能验证。粒子对照检查总数及前两项样本，其他主要对象按完整状态比较，浮点容差 `1e-7`。

`probes/` 保留代表性的历史探测；其中失败保持失败，不能替代最终汇总：

- `initial-browser.json`：早期初始化等待超时。
- `builder-fast.json`：早期初始化超过 250 ms 文档额度；随后拆分/缓存并优化运行时，没有提高初始化上限。
- `click-debug.json`：实际输入阶段触发原 8 ms 帧保护。
- `sampled-trace.json`：实际输入已通过，数值轨迹仍触发 8 ms 保护。
- `budget16.json`：改为 16 ms 后，每帧两个物理步的整关驱动仍超限。最终驱动改为一步，并分离观测/最终绘图；不改变原版断言或原生预算。
- `single-step.json`：调整后的 24 项独立专项成功记录。
- `first-unified/`：首次统一验收失败。宿主逻辑 19 项实际通过，但编排器把缺少浏览器沙箱字段误判为失败；该判定随后仅对浏览器执行，浏览器缺失字段仍拒绝。同时 Mario 在开始游玩后发生一次 16 ms 致命帧超限；这是独立的真实失败，不能归因于编排器。该次运行中修正了编排器，因此 `sourceUnchanged=false` 也如实保留。
- `recheck16.json`：上述游玩超限之后、同一浏览器实现的 24 项专项复查全部通过。随后修正编排器并补充已知限制，在新输出目录运行最终统一验收，未覆盖首次结果。

16 ms 仍不能保证 Debug 的长期稳定性：墙钟额度包含线程调度等待，现有日志不足以确定首次统一验收超限的具体来源。没有对失败执行自动重试、取消致命锁存或继续增大上限。生产页面还有 2 ms 物理软额度及绘制分帧，繁忙时可能丢弃积压、游戏时间慢于墙钟、绘制延后；不承诺稳定 120 Hz 物理或 30/60 FPS。

浏览器日志存在既有 GPU、服务与 `WebFrame LEAKED` 等诊断；完整日志保留，不把正常关闭的退出码零解释为整个 Chromium 没有诊断或已证明没有任何泄漏。本次没有修改外部马里奥原件，也没有暂存/提交工作树中的既有 MCJE 修改。
