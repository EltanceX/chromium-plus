## 1. 最终目标与范围

保留 HTML/CSS 负责页面结构、样式和原生控件，游戏逻辑、绘图指令、输入处理及页面交互全部由 Python 驱动。交付页面不包含可执行 JavaScript、JavaScript 事件属性或通过 JavaScript 转调浏览器 API 的运行依赖。

采用 Renderer 主线程 CPython，新增有类型、受文档生命周期约束的 C++ 绑定，直接调用 Blink / Chromium 已有能力。游戏状态、关卡、碰撞、计分与动画策略由 Python 实现；Canvas 栅格化、音频合成和浏览器平台功能由原生引擎承担。

首版“完整迁移”包括原项目的核心玩法与外围功能：

1. 开始、暂停、继续、重新开始、死亡、复活、检查点和通关。
2. 键盘与触屏移动、跳跃、连按与长按、失焦清理。
3. 原有地形、砖块、金币、敌人、镜头、粒子、飘字和碰撞框。
4. 速度 / 跳跃 / 重力滑块、慢动作、HUD、FPS 和进度展示。
5. 教学面板、课程切换、快捷键对话框、提示与无障碍状态。
6. 合成音效、最高分存储、全屏与完整页面源码下载。

最终课程说明和代码示例应同步改为 Python，源码下载应导出 Python 版本，不能保留可执行的原 JS 游戏作为后备运行路径。

本轮扩展不要求完整 Python 标准库、pip、任意原生扩展、Worker、asyncio、WebGL 或完整 DOM 对象映射。外链 Python / 模块加载可以后续独立设计；当前单文件游戏的迁移不能依赖尚未实现的模块下载体系。

## 3. 架构与代码边界

```text
HTML / CSS + 内联 <pyscript>
  -> 当前 Document 的 CPython 子解释器
  -> 有类型的 Python 原生模块
  -> components/python_runtime 的普通数据与句柄接口
  -> Chrome 文档适配层 / Blink 公共接口
  -> Blink 原生动画、事件、Canvas、控件、音频和浏览器服务
```

核心原则：

- 复用原生事件与动画调度，不使用 V8 执行 Python 生成的 JavaScript。
- CPython 相关对象及引用操作留在运行时组件；Blink 公共接口只传数值、字符串、结构体和不透明句柄，不跨层传 `PyObject*`。
- 节点、画布与订阅按 Document 身份和代数管理；Python 句柄不持有 DOM 裸指针，不跨文档复用。
- 注册表保持有界，同步执行沿用全局禁止重入和 GC / 禁止脚本门禁。引用释放可能执行 Python，继续在安全任务中处理。
- 同步原生操作与异步完成通知明确区分。异步结果回到 Renderer 后先复核文档、授权和执行门禁，再通过安全任务调用 Python。
- 游戏代码放在页面 / 测试数据中，不把马里奥关卡或物理规则硬编码进浏览器原生接口。

建议主要改动位置如下；新增文件名由实施阶段确定：

| 层 | 现有位置与扩展职责 |
| --- | --- |
| CPython 构建 | `third_party/cpython/`：显式内建模块、冻结依赖、来源和许可记录 |
| 运行时 | `components/python_runtime/`：typed callback 入口、预算类别、模块状态和资源句柄 |
| Chrome 适配 | `chrome/renderer/python_document_context.{h,cc}`：普通数据转换及错误映射 |
| Blink 公共接口 | `third_party/blink/public/web/web_python_script_runner.h`：新增原生 host 能力 |
| 文档控制 | `third_party/blink/renderer/core/html/python_script_controller.{h,cc}`：授权、调度、资源表和撤销 |
| 原生动画 | `core/dom/document.h`、`scripted_animation_controller.*`、`frame_request_callback_collection.*`：复用 `FrameCallback` |
| 原生绘图 | `modules/canvas/` 等现有 Canvas 层：通过符合 Blink 依赖方向的适配调用，不让 core 直接依赖 modules |
| 原型与测试 | 建议新增 `chrome/test/data/pyscript/mario/`、独立能力样例和浏览器脚本 |

方案编写只读取外部马里奥项目。后续开发先保留该文件为 JS 对照基线，在仓库内建立 Python 原型；最终外部项目输出位置在迁移阶段确定。已有 MCJE 修改不属于本方案改动范围。

## 4. 原生动画帧与预算设计

### 4.1 API 与调度语义

阶段一已实现的接口：

```python
import animation

def frame(timestamp_ms):
    update_and_draw(timestamp_ms)
    animation.request_frame(frame)

frame_handle = animation.request_frame(frame)
# animation.cancel_frame(frame_handle)
```

采用一次请求、一次实际调用的模型，不建立 Python 忙循环，不调用 `time.sleep()` 驱动主线程。时间戳使用文档对应的高精度单调时基和浏览器适用的精度限制，与系统墙钟分开。

首版每 Document 最多保留一个待执行 Python 帧请求。已有请求未执行 / 取消时再次申请应给出明确错误；回调在实际进入前消费旧请求，允许回调中申请下一帧。下一帧不得在当前刷新周期内再次调用。

窗口压力、短暂执行门禁等非致命拒绝不消费待执行请求；保持至下一个合格刷新周期，使用新的时间戳，不补发旧帧、不累积队列。不可继续的页面授权拒绝或文档停止应撤销请求。隐藏页面停止 Python 帧派发，恢复可见后按当前浏览器调度继续；游戏层重新建立 dt 基准，避免补算整段后台时间。

实现原生 `FrameCallback` 子类，经 Document / ScriptedAnimationController 请求与取消。选择回调类别时应保留面向页面代码的正常调度语义，不能借“内部回调”绕过页面冻结或生命周期限制。

### 4.2 运行时入口

现有 `InvokeCallback` 接收 click 快照，预算使用 callback 布尔标记。本轮应引入明确的执行类别，保留旧 click 语义，同时增加接收时间戳的帧调用入口。具体采用类型化 payload 或独立 `InvokeFrameCallback` 可在阶段一决定，但不得把帧伪装成 click。

回调表记录用途、所属解释器和所有权；禁止协程 / 生成器等异步 callable 或返回值沿用既有规则。调度器保存不透明 ID 与控制器弱引用，只有进入原解释器后才取得 Python callable。取消、自取消、回调中新注册、普通异常与致命停止必须分别测试。

### 4.3 额度与过载

已有初始化额度和 click 单次额度保持其语义：初始化每块 100 ms、累计 250 ms；click 每次 50 ms、128 次 DOM、4 KiB 输出；最近一秒事件额度为 250 ms、1,024 次 DOM、16 KiB 输出。不能通过引入动画入口清除既有停止原因。

阶段一使用以下**起始试验值**，阶段四根据 Debug 游戏数据将单帧上限从 8 ms 调整为 16 ms，并同步准入预留、设置说明及边界测试。其余时间额度不变；阶段七继续评估 Release 和长期游玩：

| 时间类别 | 建议起始值 | 说明 |
| --- | --- | --- |
| 单次 Python 帧 | 阶段一 8 ms；当前 16 ms，协作式 | 用于保护主线程，不是承诺每帧允许持续耗尽 |
| 最近一秒 Python 帧子额度 | 200 ms | 帧压力时延后至合格刷新周期 |
| 最近一秒输入、帧及其他交互总额度 | 250 ms | 统一结算，单独子额度不能叠加成无限总额度 |
| 初始化与清理 | 沿用既有独立额度 | 不因帧循环重置，也不计入帧间空闲 |

准入分别预留实际入口的完整单次上限，不使用 click 的 50 ms 预留作为帧准入条件。时间窗和恢复继续使用单调时钟，按实际耗时结算；多个回调不能扩大文档总额度。

DOM 调用和 Python 输出继续受文档统一窗口约束，帧初版沿用每次 128 次 DOM、4 KiB 输出的上限，并与其他交互共享每秒 1,024 次 DOM、16 KiB 输出，不能“每帧重置整文档额度”。Canvas 另按绘图操作、数据和资源计费；原生校验 / 提交耗时也应纳入对应计量。8 / 200 / 250 ms 是原始试验策略，当前为 16 / 200 / 250 ms；修改时必须同步设置说明、设计记录和测试，不静默放宽限制。16 ms 下也记录过一次间歇超限，不能据此保证 Debug 或繁忙机器上的持续稳定性，详见阶段四记录。

窗口压力采用延后、合并和必要的降频；真正的单次致命超限继续锁存停止并撤销资源。50 ms click 保护及当前 16 ms 帧保护仍为协作式，不能硬中断任意 C 操作或承诺整个 Renderer 的 CPU / 内存硬隔离。

## 5. 输入事件与页面控制

分批支持：

1. Document keydown / keyup；Window blur、Document visibilitychange。
2. 元素 input / change；Window resize 与必要的只读页面状态。
3. 元素 pointerdown / pointerup / pointercancel / lostpointercapture，以及指针捕获。

Document、Window 使用单独的有类型目标句柄，不把任意全局对象开放给 Python。事件按类别提供字段：键盘的 code / key / repeat / 修饰键、指针的 pointer_id / pointer_type / button / 坐标、表单的适当只读状态。保留 current_target、is_trusted；需要 target 时使用受所属 Document 约束的句柄或必要的目标元数据。

游戏应在输入框、文本编辑区域或对话框交互时让原生控件处理键盘。支持可访问性要求中的按钮默认激活及 tab 键盘导航，避免全部键盘输入都被游戏截获。

`prevent_default()` 与必要的 `stop_propagation()` 通过仅本次同步派发有效的临时控制令牌实现。令牌不能在回调返回后、帧回调、异步完成回调或其他解释器中使用；尊重 cancelable、passive 和浏览器正常事件语义。返回 `False` 继续不隐式取消默认行为。

指针捕获调用原生机制，遵守元素及指针有效性检查。同步操作触发的新原生事件仍受禁止 Python 重入门禁保护。游戏的 keyup、pointercancel、lostpointercapture、blur 与页面隐藏路径应共同清理输入，防止卡键。

## 6. Canvas 2D 与资源计量

本节保留原设计背景。阶段三已经实现该子集；具体 API、完整画面替换语义、资源上限和验证结果以 [Canvas 实现记录](pyscript-canvas-phase3.md) 为准。

建议提供 `canvas.get_context_2d(element_handle)` 等有类型接口，首版仅适用于当前活动 Document 的普通 HTMLCanvasElement。允许设置画布尺寸，并定义尺寸变化后画布状态及缓存失效规则。

所需子集：

- `clear_rect`、`fill_rect`、`stroke_rect`。
- 路径开始 / 关闭、move / line、arc、ellipse、fill。
- save / restore、translate、scale。
- 填充和描边颜色、线宽、虚线、透明度。
- 线性渐变和有界颜色停靠点。
- 字体、文字绘制和对齐、image smoothing。
- 后续性能所需的离屏表面与受控 `draw_surface`，无需先开放外部图片加载。

推荐“Python 记录命令、原生批量校验和提交”。Python 接口可接近 Canvas 的使用方式，实际缓冲是有类型的绘图操作，不是源码字符串、任意成员名反射或 JavaScript 代码。

提交前验证命令、参数及所有引用句柄。明确批次失败与部分执行的语义：首版对非法命令在实际绘制前拒绝整批，不宣称已经执行的原生绘制可以任意回滚。命令执行中继续保留文档有效性和停止检查。

实施阶段三必须固定以下上限并验证边界：批次字节数、每帧 / 窗口命令数、路径点数、状态栈深度、文字字节数、渐变停靠点数、画布尺寸 / 像素面积、资源数量及总表面内存。上限根据该游戏的实际峰值与合理余量确定；不可仅用“提交一次”抵消内部全部绘制成本。大面积绘制、表面复制和文字等操作需要相应成本约束。

所有数值拒绝 NaN / Infinity，字符串有界，资源带文档身份和代数；导航、画布失效和致命停止后不能继续使用。原生资源释放不在 GC finalizer 内进入 Python。

优化时先缓存可复用的角色姿态、砖块、金币等图形，减少 Python 逐像素循环；不改变游戏逻辑归 Python 的目标。画面视觉一致性与优化前后状态一致性应有独立检查。

## 7. 页面控件、平台功能与 Python 依赖

### 7.1 页面控件

提供显式操作，避免首轮引入任意属性写入：文本、value / checked、hidden / disabled、class 增删、有限属性、focus、dialog 打开 / 关闭、scroll_into_view，以及进度宽度等必要样式。属性和样式按用途限制，不能借字符串写入脚本、事件属性或任意 URL。

提供只读的窗口尺寸、页面可见性及 `prefers-reduced-motion` 偏好，覆盖原页面的窄屏布局和减少动态效果逻辑；不要求首轮映射完整的 Window 或 MediaQueryList 对象。

优先在 HTML 预先声明课程按钮、三行事件日志、图标和提示区域。Python 更新文本、属性和显示状态即可保留功能；带 `<br>`、`kbd`、SVG 图标的区域可拆成静态子节点分别控制，不要求开放任意 innerHTML。

### 7.2 音频、存储、全屏与下载

| 能力 | 建议原生子集与约束 |
| --- | --- |
| 声音 | 文档级音频上下文、resume / suspend、按时间调度音调；覆盖波形、起止频率、持续时间、延迟和音量；限制同时发声数、时长和资源 |
| 最高分 | 同源 get_item / set_item 等存储能力；沿用来源、配额、用户设置与异常，不映射到 Python 任意文件写入 |
| 全屏 | 请求 / 退出、状态和错误完成通知；使用正常用户激活及权限检查 |
| 导出 | 有界文本 / 字节下载，经过浏览器下载策略；源模板与 Python 内容一起导出，禁止成为任意路径文件写入能力 |

音频由原生音频线程合成，Python 只安排音调；不从实时音频线程回调 CPython。声音解锁与全屏请求在真实用户交互允许的同步上下文中发起，`is_trusted` 的布尔值本身不构成授权。脚本生成 click 或延后到帧任务不能伪造用户激活。

原生异步操作先采用有界的一次性完成通知，错误也回到所属页面处理；不要求同时实现完整 await / asyncio。通知到达后复核文档和代数，导航后丢弃旧通知；涉及 Python 引用释放的工作仍走安全清理。

### 7.3 数学、随机数与代码组织

按需把 math 等模块静态编入受控 CPython，审查依赖与许可证；禁止依赖开发机 site-packages 或运行时任意 DLL 加载。随机数先满足游戏随机和可注入种子回放需求，明确算法和种子；若提供标准 random，必须审查并打包其实际依赖，不把它视为当前已有能力。

当前每块内联源码上限为 64 KiB。迁移阶段可以拆为多个首次解析的内联 `<pyscript>`，复用已有文档 globals；保留来源、顺序和每块限制。不要把大量代码通过 `exec` 拼接来绕过源码或初始化额度。后续如引入外链 / 项目模块，另行定义同源策略、CSP、加载顺序、缓存、错误、取消和大小限制。

## 8. 分阶段实施步骤

## 10. 当前边界与推荐起点

不需要为该游戏开放与浏览器主进程相同的文件、网络或进程权限，也不需要放松 Renderer 沙箱。受控 loopback 来源即可开发，放开页面限制模式继续作为已有显式选项，不能替代新增能力本身的实现。

当前嵌入式 CPython 不是语言安全沙箱；执行预算仍为协作式。新增 Canvas 等资源可以建立原生资源硬上限，但不能据此声称整个 Python 堆或 Renderer 已有内存硬隔离。异步平台接口、权限拒绝和长期性能须在各阶段取得实际证据。

阶段一至五已完成原生帧调度、连续输入、批量 Canvas 2D、纯 Python 核心关卡及完整控件/教学页面交互。阶段六功能代码已接入；先完成当前标准构建、导出复测及统一验收，再进入阶段七的 Release/GPU、长期真实游玩和性能验证。每个关键部分继续保留独立样例、回归和可审阅的提交边界。
