# Python Mario：Debug 稳定性与验收

日期：2026-11-13 至 14。按本轮要求保持 `out/Debug`，不构建 Release。此前阶段六未全绿的结果继续保存在[历史验收](pyscript-mario-platform-validation/README.md)，不覆盖为成功。

## 排查与修复

旧版追踪器给每个 Python frame 开启 `f_trace_opcodes`，因此每条字节码都要经过 C++ trace 回调、capsule 读取和事件计数；即使该事件不实际检查时间，仍有回调开销。游戏物理、推导式和绘图构建都处在这一热路径。

现在使用 CPython 的行、调用、返回及异常事件，每个收到的事件都检查时间和已锁存停止；每 64 个事件复查完整页面策略。CPython 3.13 对跳回同一源码行的后向跳转也派发行事件，因此同一行的 `while True: pass` 和内联列表推导式仍受保护。桥接前后、入口和结束的完整检查保留。新增两项 Runtime 回归，覆盖单行死循环、大推导式、捕获超时后不能复活，以及 25 ms 原生等待仍触发 16 ms 帧停止。

初始化 100 ms/块及累计 250 ms、事件 50 ms、帧 16 ms、帧窗口 200 ms/s、交互窗口 250 ms/s、输出/DOM/绘图/音频资源限制和 Renderer 沙箱均不变。没有改成 CPU 时间额度，没有修改 CPython 上游源码或关闭 Debug、符号及 PDB 检查。

超限日志新增 wall_ms、cpu_ms、max_check_gap_ms 和 trace_events。CPU 计时不可用时新版记录 -1；这仅是诊断，不参与准入或扣费。早期探测日志中的 cpu_ms=0 没有区分不可用，不可据此断言那次执行完全没有 CPU 工作。

### GPU 冷启动与恢复测试时序

默认图形后端首次直接打开游戏时，背景缓存绘制触发原生共享 GPU 上下文的惰性初始化。失败日志记录初始化块墙钟约 140 ms、最大检查间隔约 138 ms，超过原有 100 ms。此前在其他 Canvas 测试之后打开游戏会复用已准备的上下文，因此仅看暖启动不能发现这一边界。

现在 Blink 在已授权、有被接受的 Python 块且 DOM 含 Canvas 的页面进入解释器前准备原生共享 GPU 上下文。准备过程处于文档保活和 Python 重入门禁之内，返回后重新检查停止、来源、文档和脚本执行授权；没有 Canvas 或已拒绝页面不触发准备。准备失败仍由原生绘图机制处理后续回退。Canvas 分配、命令预检、绘图提交及桥接调用仍在原有额度内。准备原生依赖本身可能阻塞 Renderer，这不构成无卡顿承诺。

新增两项 Blink 回归：确保准备发生在创建解释器之前，并验证无 Canvas、拒绝来源和准备中撤权。修复前两项均失败，保留 `gpu-before` 结果；修复后 `gpu-after` 两项均通过。

首次延长测试还暴露了驱动的恢复竞态：冻结后立即点击继续，下一帧才观察到新的 input epoch，因此页面按既有规则再次暂停。仅增加等待仍失败，继续读源码确认 `PageHandler::SetWebLifecycleState` 的 frozen 调用 `WasHidden()`，而 active 只解冻；当该标签页已被选中时，单独 bringToFront 不一定再次执行可见状态切换。

驱动现在通过创建、激活一个临时空白标签页，再回到游戏并关闭空白页来恢复真实可见状态；等待页面可见、有焦点且原生帧至少推进两次，再断言保持暂停并点击继续。页面的失焦/隐藏清输入及自动暂停规则保持原样，没有用重试吞掉产品超限。`soak-gpu-cold-fixed-2` 的全新 profile 直接打开游戏并完成 60 秒交互，包含冻结/恢复和窄宽屏切换；结果通过，期间源码及二进制哈希一致。

### Debug 对象恢复

新增回归和 controller 已编译，链接时分别遇到四个旧对象的异常：`v8_internal_runtime_flags.obj` 的节名称损坏、`custom_password_heuristics.obj` 的文件头无法识别、`v8_get_animations_options.obj` 的字符串表末尾缺少终止符，以及 `custom_element_registry.obj` 的 CodeView 类型记录损坏。逐个保存原件、SHA-256、失败响应文件及日志后，仅删除已验证位于 `out/Debug/obj` 内的指定输出，使用 `SCCACHE_RECACHE=1` 定向重编。之后 chrome/blink_unittests 的标准 Debug 链接成功，没有清空缓存或关闭 Debug/PDB/GHASH。对象异常的更底层来源没有在本轮确定。

最初节名称扫描漏检了末尾终止符，之后按 LLVM 字符串表初始化逻辑补齐，定位到与链接错误一致的第 312 节。归档保留早期漏检结果和修正后的扫描，不将扫描无问题等同于链接已经成功。尝试使用原生 `llvm-readobj` 时发现该工具未随本机工具链安装，未将此尝试作为有效验证；后续使用只读 COFF 扫描和正常链接验证。

## 调度停顿与保护边界

在独立测试 profile 中，对实际运行 Python 的 Renderer 主线程注入 20 ms 暂停，并保证每次 SuspendThread 都在 finally 中 ResumeThread，复现 frame 45 停止：墙钟约 23 ms、两次检查最大间隔约 20 ms。这证明调度停顿足以触发原有保护，不能证明历史 frame 2340 的全部耗时来源。最初两次分别误选浏览器线程和 WebUI Renderer，未命中 Python；保留为无效探测，不当作产品成功。

修复通过降低正常执行开销增加余量，不保证在操作系统暂停线程超过 16 ms 时继续游玩。强制暂停、原生阻塞或实际工作超限仍应锁存停止；这种墙钟保护保留。解释器的协作式检查也不能抢占一个尚未返回的任意 C 调用，不能作为语言安全沙箱或硬实时保证。

## 单次性能对照

同一份默认起点整关轨迹，2773 个物理步，测量 `update(STEP)`，每个原生动画回调一步，观测与最终绘图另占回调。外部诊断副本只加入计时，不更改原版预期、物理步长、输入或预算。两次均通过 15 条轨迹中的整关对照；这不是持续绘图性能或人工键盘通关。

| 每步墙钟耗时 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 平均 | 2.208 ms | 1.424 ms |
| p95 | 3.128 ms | 2.632 ms |
| 最大 | 6.090 ms | 5.345 ms |

平均减少约 35.5%。这是本机单次诊断对照，包含追踪和页面策略成本，不是独立 CPU 采样、长期稳定性结论或跨设备性能承诺。

## Debug 验收

标准五目标 Debug 构建及 18 组统一验收完成，**460 项全部通过**：224 项原生单测、29 项宿主逻辑、207 项浏览器检查。Runtime 为 82 项，Blink HTMLPyScriptElement 为 80 项。2026-11-14 本地时间约 00:45 至 00:53 运行，`passed=true`、`sourceUnchanged=true`，875 个功能输入在验证期间保持不变。此前行追踪修复后、GPU 入口和最终驱动修复前的 458 项成功另存为中间结果。

独立硬件 GPU 运行 **36 项全部通过**，包含 35 项 Mario 检查及一次 300,345 ms 延长交互：259 轮输入、25 次冻结恢复、51 次采样，随后导航/刷新与正常关闭通过。通过 `SystemInfo.getInfo` 确认为 AMD Radeon Graphics、ANGLE D3D11、驱动 `31.0.21912.14`，Canvas 2D、GPU 合成和栅格加速启用。它与软件绘制的统一入口分别归档，重复覆盖不累加进 460 项。

硬件测试期间源码和十个二进制哈希保持一致，并与最终统一验收对齐。延长采样的 DOM 计数范围为文档 1–3、节点 431–949、JS 监听器 1–6；这些计数包含原生页面及待 GC 文档，不能据此宣称整个 Python 堆无泄漏或有硬内存上限。最终采样的回调主体生命周期峰值约 8.106 ms、最近样本 p95 约 4.882 ms；它们不包含所有宿主收尾和最终 GPU 栅格，也不是 FPS 或硬实时保证。

完整结果、所有失败、输入/二进制哈希、截图和恢复记录见[证据目录](pyscript-mario-debug-validation/README.md)、[最终统一结果](pyscript-mario-debug-validation/final/summary.json)及[审计](pyscript-mario-debug-validation/final-audit.json)。外部 Mario 原件及本轮开始时的 32 份 MCJE 文件和生成页面字节保持原样。平台源文件同步了生成页面既有的一处空行差异。

浏览器驱动新增 `--case-filter=文本`、`--graphics=software|default`、`--soak-seconds=0..600`。过滤运行显式记录 caseFilter、skippedCases 和实际执行数量，没有匹配时失败。默认统一入口仍执行全部 35 项 Mario 检查；延长测试另加一项，不能把重复覆盖再累加为新的独立用例。

5 分钟测试使用可信方向/跳跃输入，周期性暂停、冻结/恢复、窄宽屏切换和重开，保存帧推进、页面测量、DOM 计数及截图。它是有明确时长的压力检查，不代表数小时游玩、Python 堆硬上限或声音的主观听感。页面仍无 JavaScript 运行依赖，CDP 仅为外部验证工具。Release 按用户要求暂不构建。
