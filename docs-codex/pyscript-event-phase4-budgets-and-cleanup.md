# 原生 Python 点击事件：阶段四交互预算、导航与安全清理

日期：2026-11-09（Asia/Shanghai）。接续[阶段三](pyscript-event-phase3-native-click-dispatch.md)，总体设计见[点击事件方案](pyscript-click-events-implementation.md)。

## 预算类别

运行时将初始化、点击回调和解释器清理分别计量。初始化额度保留原值，点击不再消耗初始化的终身额度。

| 资源 | 初始化 | 单次点击回调 | 每 Document 事件窗口 |
| --- | --- | --- | --- |
| 执行耗时 | 每块 100 ms，累计 250 ms | 50 ms | 最近 1 秒累计 250 ms |
| DOM 调用 | 累计 1,024 次 | 128 次 | 最近 1 秒累计 1,024 次 |
| Python 输出 | 累计 16 KiB | 4 KiB | 最近 1 秒累计 16 KiB |
| 订阅数量 | 与事件共用最多 128 项 | 同左 | 同左 |
| 解释器清理 | 独立 50 ms 尽力预算 | 与初始化和事件停止原因分离 | 不使用事件窗口 |

时间由可注入的单调时钟计算，只累计实际进入运行时后的耗时，包括桥接、异常格式化和相关 Python 引用释放；两次事件之间的空闲不计入执行消耗。这是执行期间的经过时间，不能称为进程 CPU 硬配额，也不能硬中断任意 C 操作。

事件输出按 Python stdout、stderr 和异常诊断的 UTF-8 字节计量，三者共用额度。浏览器添加的固定来源前缀、停止通知和限频提示不作为 Python 文本重复收费；因此控制台显示的总字节数可以包含少量固定开销。Blink 对事件结果直接使用运行时的计量结果，初始化与解析诊断继续使用原有的独立控制台上限。

## 窗口准入和结算

运行时保留每次回调完成时的耗时、DOM 调用数和输出字节数。准入时移除已过期的记录，并要求窗口余量足以容纳完整的单次上限：50 ms、128 次 DOM 和 4 KiB 输出。回调返回后按实际使用量结算，普通 Python 异常也收费。

窗口采用完成时间归属：一次回调的全部消耗保留到其完成一秒后，不拆分跨越窗口边缘的执行片段，因此在边界上略保守。记录最多保留 1,024 项；更多微小回调合并到最新记录并使用最新完成时间，进一步保守地保留消耗，避免无界增长。

`PythonContext::CanInvokeCallback()` 是不进入 Python 的主线程准入检查。Chrome 将它接到公共上下文接口，Blink 在当前策略和 CSP 检查通过后、撤销原生 `once` 监听之前检查余量。检查与同步调用之间不允许其他 Python 进入；这段空闲只会释放窗口额度，不会增加消耗。运行时实际进入时仍复核一次。

窗口不足时不取出 Python callable、不消费 `once`、不借出 DOM host，也不排队。每文档最多每秒一条窗口提示。窗口恢复后只处理新的点击；已经跳过的事件不会补发。

单次时间、DOM 或输出超限，以及执行期间文档失活，仍锁存致命停止。窗口过期、切回初始化入口或新一次调用都不能清除停止原因。Blink 撤销该文档的全部订阅和 DOM 代数，等调用返回后释放解释器。

## DOM 计量与清理

原生 `BudgetedDomHost` 对每次实际桥接调用收费，错误调用也消耗已进入桥接的额度。初始化计数和事件单次计数分离，窗口总计由原生运行时统一维护。Blink 同时保留初始化与事件单次的防御性上限，事件不再累加到旧的初始化 DOM 计数。

安装失败的内部 listener 回滚仍可在预算停止后撤销原生状态，不是页面 API，不额外借出 Python / DOM 执行能力。回调返回值析构、异常格式化和回调注册表引用释放不继承用户回调的 DOM 能力。

`Document::Shutdown()`、`document.open()` 和执行上下文销毁继续使用既有停止入口。先标记停止、失效句柄和撤销原生监听，再通过安全任务销毁上下文。销毁任务避开 GC 原子暂停、当前线程 sweeping、禁止脚本区域和其他 Python 执行；任务队列在进程关闭时丢弃的资源仍交给进程退出回收，不在任务闭包析构时运行 Python。

回调中发生文档失活时，返回后的 stdout、stderr 和错误不再写回已失活页面。解释器清理不在当前 Python 栈中执行。fragment 导航保留原上下文；新 Document、iframe 移除或替换不能调用旧解释器。保持 Python 文档的 BFCache 排除和 prerender 拒绝。
