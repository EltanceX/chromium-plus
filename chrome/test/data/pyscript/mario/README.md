# 原生 Python Mario 游戏与教学面板

编辑本目录的 Python 文件及 `shell.html`，运行：

```powershell
python chrome/test/build_pyscript_mario.py
python chrome/test/build_pyscript_mario.py --check
python chrome/test/pyscript_mario_unittest.py -v
```

输出为上级目录的 `mario.html`。页面仅有有序内联 `<pyscript>`，共 11 块，每块最多 64 KiB，共享当前文档 globals；没有外链 Python 加载器、`exec`、JavaScript 或事件属性。

- `state.py`：原版常量、7040 像素关卡、角色/游戏状态、固定种子随机效果。
- `physics.py`：原版默认参数、分轴碰撞、可变跳高、宽限跳跃、提前跳跃、敌人、计分与状态转换。
- `drawing.py`：原生 Canvas 缓存、可见对象绘制、镜头、粒子和飘字。
- `controls.py`：键盘/指针、按钮键盘长按、页面恢复、固定步长、低频 HUD、测量。
- `ui.py`：参数、原生控件、tab/课程/对话框、焦点、日志、提示及响应式画布。
- `boot.py`：初始化首次复制、监听安装、原生帧请求。

构建后的本机 Chrome 必须启用 PythonScript，并在“内核调试”中允许实际访问的顶级 HTTP 来源。可在仓库根目录用 `python -m http.server 8000 --bind 127.0.0.1` 启动服务，允许 `http://127.0.0.1:8000` 后访问 `http://127.0.0.1:8000/chrome/test/data/pyscript/mario.html`。页面保留 nonce CSP 和 Renderer 沙箱，默认解释器/站点设置仍然生效。

## 原版对照与确定性

原项目只读路径 `C:/VD/Projects/mario/index.html`；SHA-256：
`53b556316bbc25a5c2c80b046be836dbaaea8aa5c25e85a2cf5f29a4b4bc9ef1`。

`pyscript_mario_reference.mjs` 从该原件提取原函数，在 Node VM 中屏蔽外围 UI/声音/存储副作用，仅把 `Math.random` 换成与 Python 相同的 xorshift32。它保存 `reference.json`，普通回归直接读该快照，无需外部原项目。重新生成须显式运行并审查差异；原件哈希不符会拒绝运行。

`route.json` 是原版默认初始状态下的一条整关输入记录。只含跳跃按下/松开、持续向右和物理步数，没有坐标改写、无敌或计分修改。2773 个 `1/120` 秒步后通关：25 金币、5170 分、3 生命、0 死亡。生成时采用离线分支搜索，普通回归只回放固定记录；途中六个状态检查点同时对照原版和 Python。

其他隔离场景用明确声明的起始状态，覆盖顶砖、踩怪、受伤、掉坑、最后一命、超时、检查点复活及通关庆祝。它们不能代替上述从默认起点出发的整关记录。

随机算法为 xorshift32，左移 13、无符号右移 17、左移 5，每次截断为无符号 32 位；结果除以 `2**32`。默认种子 `0x4D415249`，零种子映射到默认值。重开重置种子。它只服务游戏效果，不适用于密码学，不改变 CPython 哈希随机种子，也不宣称支持标准库 `random`。

## 当前边界

物理固定 `1/120` 秒步长，帧间 dt 最大 50 ms，每帧最多 6 步；实际页面还有 2 ms 的物理工作软额度，完成当前步后检查，负载过高时丢弃积压并计入 `dropped_s`。它不能中断当前物理步，也不保证实际每秒完成 120 步；Debug 或繁忙机器上游戏时间可能慢于墙钟。确定性逻辑回归关闭墙钟软额度，另用注入时钟验证软额度丢弃行为。

隐藏、失焦、输入 epoch 变化时清输入、自动暂停并重置累计时间。命令构建和提交分开占用两个原生帧，绘制上限 30 Hz；负载过高时延后绘图。测量 HUD 每 250 ms 准备一次，每回调最多更新一个测量文本；页面 HUD 按固定键合并最新值、去重，每帧最多两次 UI 写入并检查 4 ms 软工作时间。记录物理、构建、提交、包含 HUD 的回调主体总耗时、最近 32 个样本的 p95、生命周期峰值、帧间隔、实际步数及丢弃时间。它们不含回调结束后的宿主清理、最终 GPU 栅格，也不代表 Release 性能结论。

阶段四根据 Debug 实测将试验性的单帧保护从 **8 ms 改为 16 ms**；原来的 8 ms 有偶发致命停止，见阶段记录中的失败证据。200 ms/秒帧子额度、250 ms/秒交互总额度、输出/DOM/绘图/资源额度和 Renderer 沙箱保持原值。超限继续锁存致命停止；16 ms 仍是协作式保护，不是持续满额运行许可。

16 ms 下仍记录过一次开始游玩后的致命帧超限，同一源码的独立复查全部通过；尚未确定该次原生工作或线程调度的具体耗时来源。当前使用单调墙钟计时，不能保证在系统调度抖动或 Debug 负载下持续游玩不会停止。阶段七需继续验证 Release/GPU 和长期真实游玩，不能用一次回归通过推断稳定帧率。

最多八个原生资源：页面画布及七个缓存。静态地形在 1760×152 缓存中以四分之一比例绘制，屏幕再还原世界尺寸；背景及角色也使用缓存。动态物件按镜头裁剪，模拟粒子池最多 128、飘字最多 32，每次最多绘制 24 个粒子。这里简化了地面细节、角色步态、远景和粒子淡出；原版物理、关卡、碰撞和计分仍作数值对照。不会静默增加资源额度。

阶段五提供三参数滑块、0.45× 慢动作、碰撞框、恢复默认、八节 Python 课程、三个 ARIA tab、运行状态/进度、三条事件日志、限时提示，以及学习地图/快捷键原生对话框。方向和跳跃按钮支持 Space/Enter 长按/松开；原生控件获得焦点时清输入并让行游戏快捷键。打开对话框暂停，关闭后不自动继续。窄屏逻辑宽度 790，宽屏 1120；原生滚动遵循减少动态效果偏好。

声音、最高分持久化、全屏和导出属于阶段六。当前最高分只保留在文档内，不应标记为原项目完整迁移。阶段五接口及验收见 [实现记录](../../../../../docs-codex/pyscript-mario-phase5.md)。
